# 서브 에이전트 스레드

Direct Gateway는 일반 Codex의 부모/자식 메타데이터와 Orca의 실제 작업 배정 기록으로 자식 에이전트를 자동으로 모읍니다. 일반 `/fork` 대화는 자식으로 분류하지 않습니다.

Discord의 일반 Codex 작업 스레드에서 `서브 에이전트 2개로 구현과 리뷰를 나눠 진행해줘`처럼 요청하세요. 별도 명령이나 Orca 없이 기존 Codex 세션으로 전달됩니다. Codex에서 생성된 자식은 실시간 동기화 중에도 발견해 아래 구조에 연결합니다. Codex의 서브 에이전트 활성화·동시 실행 제한과 프로젝트 지침은 그대로 따릅니다.

- 부모 작업의 채널에 `작업 이름 · agents` 안내 스레드를 만듭니다. 부모 스레드에 참여한 Operator 사용자를 초대하고 처음 한 번 개인 멘션합니다. 참여자를 찾을 수 없으면 멘션 없이 생성합니다. 안내 스레드와 자식 스레드에서는 Operator 역할을 멘션하지 않습니다.
- 자식 작업은 같은 권한을 복사한 `<컴퓨터 채널>-subagents` 채널의 개별 스레드로 만듭니다. 자식에게는 사용자를 자동 추가하거나 진행·질문·완료 멘션을 보내지 않습니다.
- 안내 스레드에는 새 자식 링크를 추가합니다. 안내 스레드와 이동 안내 스레드에서는 명령이나 에이전트 대화를 실행하지 않습니다.
- 기존 자식 스레드는 기록을 보존한 채 이동 안내를 남기고 보관합니다. 새 스레드는 실제 세션에 연결됩니다.
- 자식 이름에는 Codex 작업 경로·이름 또는 Orca 작업 제목을 사용합니다. 관계를 증명할 수 없는 과거 터미널은 추측해서 재분류하지 않습니다.

## 자식에게 답하기

Orca 작업은 개별 스레드에 텍스트를 보내면 기존 CLI 소유자에게 전달됩니다. 일반 Codex 자식은 부모 에이전트에게 **해당 자식 ID로 메시지를 전달하라는 요청**을 보냅니다. Connector가 실행 중인 부모는 현재 턴에 추가 입력으로 전달하고, 쉬고 있는 부모는 같은 세션에서 이어갑니다. 부모가 실제 전달을 수행해야 하며, 봇 접수 알림만으로 자식에게 전달 완료되었다고 보장하지 않습니다. 닫힌 자식을 임의로 새 에이전트로 대체하지 않습니다. 자식의 공개 답변과 진행 내용은 개별 스레드에 표시됩니다.

Codex 자식의 명령·첨부 파일은 부모 스레드에서 처리하세요. 부모 대화에 Discord 입력이 가능한 상태여야 합니다. ChatGPT/Codex 앱, Orca 및 Connector가 소유한 세션의 기존 입력 경로를 사용하며, 연결되지 않은 일반 CLI의 실행 중 입력을 새로 지원하는 기능은 아닙니다.

## 표시 및 운영

Discord는 중첩 스레드를 지원하지 않습니다. 안내 스레드의 링크로 모으는 구조입니다. 공개 자식 스레드가 목록에 보일 수 있고, 직접 들어가 참여한 스레드는 사이드바에 표시될 수 있습니다. 개별 사용자의 알림 설정은 봇이 바꿀 수 없습니다. 서버·채널 알림은 `멘션만`을 권장합니다.

실시간 표시에는 `/realtime on`이 필요합니다. 일반 Codex 관계는 Orca 없이도 동작합니다. Node 22 이상에서는 내장 SQLite를 사용하며, Node 20에서는 `sqlite3` 명령이 필요합니다. Orca 관계는 양쪽 세션의 현재 소유 프로세스와 배정 시점의 터미널 incarnation을 확인할 수 있을 때만 등록합니다. 등록한 관계는 터미널 종료 후에도 유지합니다.

Gateway만 업데이트·재시작하면 됩니다. 실행 중인 Worker를 재시작할 필요는 없습니다. `.connect/state.json`의 인덱스·자식 연결과 전송 위치 기록을 보존하세요. 이 기능은 Codex 자식 및 Orca의 Codex 작업을 대상으로 합니다.
